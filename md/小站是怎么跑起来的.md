# 小站是怎么跑起来的

趁着改首页，把整个站子从头走了一遍。代码不多，压缩过，读起来像一张折起来的图纸。理清之后，它其实只做三件事：把地址译成页面，把文字译成文章，把文件送上服务器。

## 一、三个模板撑起所有页面

整站三种页面：首页、文档、找不到。它们都不是独立的 HTML，而是写在 `index.html` 里的三个 `<template>`——平时不露面，等脚本按地址挑一个，克隆出来。

地址只看 `#` 后面那一段：空的是首页，`#/docs` 是文档列表，带 `?d=` 的是一篇文章，带 `?category=` 的是一个分类。脚本先分辨是不是本站的链接，再看这一段长什么形状。因为认的只是 hash，从首页点到文章页，浏览器根本没发新的页面请求——整站切换之所以快，根子在这里。

## 二、文章是怎么变成页面的

全站要读文件的，只有“打开一篇文章”这一件事：去 `md/` 取那个 Markdown。

取回来是一段纯文本，先交给 Marked 解析成 HTML，再交给 DOMPurify 洗一遍，脚本、事件属性这些不安全的东西一概滤掉，额外放行的只有视频标签和它要用的几个属性。洗完按短码存进内存，同一篇再打开就直抵屏幕，不必重新下载。

短码由路径算出：一个固定的盐值，加上文件路径，做一遍哈希，取 36 进制六位。同一篇文章，短码永远一样——改标题、改分类、挪目录，链接都不会断。

## 三、目录、图片与相册的规矩

正文的一级标题会被摘掉，它和页面顶上那一行重复。目录只收二级标题，按顺序编号，点哪条滚到哪节。全文若连一个二级标题都没有，目录的位置就写一句话：这篇手记很短，慢慢读。

图片不在文章里写域名。只写 `../static/...` 这样的相对路径，渲染时由一处配置拼成完整地址；换图床改那一行就够，十几篇文章都不用动。图片走外链，浏览器默认带上 referrer，图床见了会当盗链拒掉，于是页头干脆把它关了。

几张图或几段视频挨着放，会被合成一个相册：横向排开，一次露一张，靠滑动或方向键翻。首页那条还会自己走，五秒一张；鼠标停上去、焦点落进去、大图弹出来、它滚出屏幕，任一情形都会停。

## 四、首页那三块

最近更新取三篇最新的。时间不按访客的时区算——字符串写几点就是几点，统一按北京时间折算成时间戳，再据此排序。

精选那三篇另按手工填的序号排。若交给时间，刚发布的一篇会自动顶掉主推，编辑的意图便没有落脚处。

签一天一支。随机数取自浏览器自带的来源，抽到什么当天存下，第二天重来；关掉再打开，还是那一支。底部那句寄语来自外部接口，八秒没回就退回原来那句，首页其余各处都不等它。

## 五、换页那一下，和最后一步

点链接不会立刻换。先让当前内容淡出八十毫秒，再换模板、重建页面，最后淡入两百二十毫秒。淡出那一段里内容还在、高度不变，正好盖住滚动条跳回顶端的那一下。连点两下，只认最后一次的目标。

写完还不算上线。推到 Gitee 之后，服务器上跑一次脚本：拉一份干净的副本，同步到待发布目录，顺手给 js 与 css 的链接加上内容指纹——文件一变指纹就变，浏览器不会捧着旧缓存不放。末了把整个目录镜像过去，目标里多出来的文件一并删掉。

整条链上没有数据库，没有后台，也没有构建步骤。要改什么，改文件、推一次，剩下的交给脚本。
